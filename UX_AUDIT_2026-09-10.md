# Algan UX audit — 10 September 2026

## Executive assessment

Algan's strongest UX is its short authoring loop: construct an object, spawn it, record changes with ordinary methods, and choose timing with `Seq`, `Sync`, `Lag`, or `Off`. The existing `Scene.save_video`, `Scene.save_frame`, `Scene.view`, `SETTINGS`, and material APIs provide a coherent foundation. I recommend preserving that model rather than introducing a second animation language or a large set of synonyms.

The largest remaining opportunity is **predictability across boundaries**: construction versus later setters, anchors versus visual centers, authored time versus render time, global settings versus per-scene choices, Python versus Manim conventions, and asynchronous viewer requests versus the state currently on screen. Several of these boundaries contained concrete defects; this audit fixes eleven related bug families without renaming established public methods.

The next API work should prioritize an inspectable render plan and authoring diagnostics, a unified background contract, consistent ownership/coordinate documentation, and reliable IDE discovery. Naming improvements are worthwhile where a name actively suggests the wrong unit or concept. Cosmetic abbreviation and wholesale renaming are lower priorities.

## Scope and evidence

**Audited base:** `d055e77f10dc28e3908329158b2b41d80826e9da` (`master`)

This was a source-based UX and correctness audit, not a usability study with participants. I inspected the public namespace and authoring guidance, Scene lifecycle and export entry points, animation contexts, settings/presets, Mob transforms/layout/hierarchy, groups, color/text/plotting entry points, image/background handling, Project output routing, CLI/daemon behavior, Manim adapters, and the interactive viewer. Findings were compared against current implementation and existing regression tests rather than treating older TODOs as current facts.

The renderer's physical models and numerical kernels were not re-audited, benchmarked, or modified. New local JavaScript tests use a deterministic DOM/network boundary, not a real browser. Local Python source-isolated checks use real source and Torch with renderer/registration boundaries replaced; they are not full-package integration tests. The validation section records these distinctions explicitly.

Source references below are repository-relative paths and symbols at the audited base or this branch. Proposed spellings are designs, **not APIs implemented by this patch**.

## 1. Bugs fixed

### B01 — Scene constructor did not normalize supported background strings

**Before:** `Scene(background="red")` or a hex/image-path string bypassed `set_background`'s normalization. Initialization subsequently treated the string as tensor-like background data and failed.

**Fix:** Constructor background preparation now routes through the existing setter after preserving the legacy callable initialization path. CSS names, hex strings and image paths use the same conversion code as later setter calls.

**Evidence:** `algan/scene.py: Scene.__init__, Scene.set_background`; regression tests cover CSS/hex/Color values and an actual temporary image file. This does not unify the two Python callable protocols; see R03.

### B02 — Explicit constructor backgrounds could be replaced by render defaults

**Before:** Even a valid constructor color left `background_is_set` false. A subsequent default-setting call with `overwrite=False` could replace the user's explicit choice. Reset also forgot that the initial background had been explicit.

**Fix:** Record whether a background was explicitly supplied and restore that status on reset. An implicit initial background still defers to global render defaults; a caller's explicit choice does not.

**Evidence:** `algan/scene.py: Scene.__init__, Scene.reset`; tests exercise non-overwriting setter calls before and after reset. No rendering-default policy or callable signature was changed.

### B03 — Non-finite animation timing escaped validation

**Before:** The negative-duration guard accepted NaN and positive infinity; non-numeric values could fail with a low-level comparison error. These values can poison timeline arithmetic instead of producing a useful error at the authoring line.

**Fix:** Shared runtime validation requires a finite, non-negative numeric value, preserving `None` where it means inheritance. Errors name the offending timing parameter. Existing negative-runtime behavior is retained.

**Evidence:** `algan/animation_timeline/animation_contexts.py: _reject_negative_runtime`; `Scene.wait` uses the same guard. Tests cover `Seq`, `Sync`, `Lag`, `runtime`, `runtime_per_part`, and waits, including unchanged cursor state after rejected waits.

### B04 — Line layout depended on direction magnitude

**Before:** `arrange_in_line(RIGHT, buffer=...)` and `arrange_in_line(3 * RIGHT, buffer=...)` produced different spacing. A direction describes orientation, whereas `buffer` already specifies distance. Zero vectors could silently collapse a layout.

**Fix:** Normalize validated layout directions and alignment directions; reject zero vectors. Normalize by the largest component first so very small or very large finite magnitudes do not underflow/overflow the normalization step. Grid directions use the same guard.

**Evidence:** `algan/mobs/group.py: _layout_direction, arrange_in_line, arrange_in_grid`; tests cover scaled directions, extreme finite magnitudes, and rejection before member movement.

**Compatibility:** Scripts that intentionally encoded spacing in direction magnitude must use `buffer` instead. Unit-direction behavior is preserved.

### B05 — Center-based arrangement actually used anchors in two paths

**Before:** `start_at_first=True` could move the first object's visible center when its anchor differed from its geometry center. `arrange_between_points` promised evenly spaced centers but assigned evenly spaced anchors.

**Fix:** Start from the first visual center, preserve the first member's alignment offset, and compensate for each object's anchor-to-center displacement when placing centers between endpoints.

**Evidence:** `algan/mobs/group.py: arrange_in_line, arrange_between_points`; tests use a nested Group with a deliberately offset anchor. This does not change the general meaning of `.location`.

### B06 — Descendant queries lost the component filter

**Before:** `get_children(generation=1, include_components=False)` failed to forward `include_components` during recursion, allowing structural components to reappear at deeper levels.

**Fix:** Forward the flag through recursive generation traversal.

**Evidence:** `algan/animatable_base/mob_hierarchy.py: get_children`; a regression test distinguishes ordinary grandchildren from components.

### B07 — Invalid Group members could trigger recursion or obscure attribute errors

**Before:** Nested traversal treated strings as iterables, eventually recursing forever on individual characters. Other malformed Group arguments reached `.scene` accesses without an explanatory member-type check.

**Fix:** Treat strings and bytes, including subclasses, as atomic traversal leaves. Validate Group members against the existing `Animatable` base before scene lookup or Group registration, raising a descriptive `TypeError`.

**Evidence:** `algan/utils/python_utils.py: traverse`; `algan/mobs/group.py: Group.__init__`. Tests cover nested text/bytes and invalid members, checking that rejection does not register an extra actor. This is not a redesign of Group ownership or a guarantee that every later constructor failure is transactional.

### B08 — Project frame exports mishandled directory targets

**Before:** Project's frame-path prefixing could turn a directory target into a sibling filename instead of putting the image inside it. That differed from ordinary Scene output routing.

**Fix:** Recognize existing directories and paths ending in the platform separator before adding the default filename and project frame prefix. Preserve bare-name routing to the project's screenshot directory and explicit-parent routing to the requested parent.

**Evidence:** `algan/project.py: _ProjectSceneRun.prepare_frame_path`; tests cover existing directories, trailing separators, Path objects, and the unchanged bare-filename case.

### B09 — Old viewer frame requests could overwrite new state

**Before:** A frame from an old resolution could finish after its replacement and redraw the canvas with the wrong bitmap. An old failed image request could delete the replacement cache entry. A stale frame error could change the status back to loading after a newer frame had displayed successfully.

**Fix:** Match both frame and resolution epoch before drawing or reporting an error. Remove a failed cache entry only when it still belongs to that exact request.

**Evidence:** `algan/viewer/static/viewer.js: frameImage, showFrame`; deterministic JavaScript tests deliberately resolve requests in the wrong order.

### B10 — Viewer inspection and attribute responses could overwrite newer selections

**Before:** An older pixel inspection or attribute request could finish after a newer one and replace the current panel, including when both requests referred to the same pixel or Mob. Some polling paths checked state, but final responses and errors did not consistently do so.

**Fix:** Assign monotonically increasing request IDs and validate request, frame, resolution epoch, and relevant selection before using results or errors. Abandon obsolete pixel polls before issuing another request.

**Evidence:** `algan/viewer/static/viewer.js: inspect, showAttributes`; tests cover repeated requests, changed selections, changed frames/resolutions, and stale failures. This prevents late overwrites; it does not claim continuous live attribute refresh during playback.

### B11 — Failed viewer hierarchy expansion could not be retried

**Before:** The hierarchy row marked its children as loaded before the request succeeded. A failed request left the branch empty and subsequent expansion treated it as already loaded.

**Fix:** Keep separate loading and successfully-loaded flags. Show an actionable inline error, allow collapse/re-expand to retry, and share an in-flight load rather than issuing duplicate requests.

**Evidence:** `algan/viewer/static/viewer.js: nodeRow`; a deterministic regression test rejects the first request, retries successfully, and checks that expansion during a pending request does not duplicate it. The test failed before the fix and passed afterward.

## 2. Prioritized API and feature recommendations

Priority describes recommended implementation order, not a claim that every item is a defect. **P1** means high-value next work; **P2** means a useful follow-on; **P3** means defer until more user evidence warrants it.

### R01 — P1: Add a render plan and authoring preflight

There is already `algan check` for installation health, and rendering already performs memory/device checks. The missing author-facing layer is a cheap explanation of *this scene's* intended render before expensive compilation or output begins.

Proposed entry points are `Scene.validate()` and `Scene.render_plan(...)`, with the same class/instance binding and settings resolution as the existing save methods. A plan should report resolved output paths, renderer/device, dimensions, frame rate, frame/time interval, sampling settings, alpha/compositing mode, required assets, and settings provenance. Validation should identify never-spawned renderable actors, incompatible scene ownership, unavailable assets/fonts/encoders, and incompatible output modes without pretending to prove image correctness.

Return structured findings with severity, object name, authored source location when available, and a remedy. Reuse existing validators and resolution helpers; do not build a parallel set of rules. Keep estimates clearly distinguished from measured memory or runtime. Acceptance tests should assert that planning does not advance timelines, change settings, allocate a full render arena, or write output.

**Anchors:** `algan/scene.py`, `algan/render_loop.py`, `algan/errors.py`, `algan_cli.py`, `algan/settings/`.

### R02 — P1: Expose stable timeline inspection and named cues

Algan has powerful temporal composition, but diagnosing timing still leads users into `animation_manager.context.timespan` and related internals. Add a read-only authored-timeline description showing context hierarchy, local versus resolved time, runtime scaling, and the originating operation. Connect it to the viewer rather than creating a separate debugger UI.

Named cues would let educational scenes associate narration beats, explanatory labels, and selected stills with semantic names instead of brittle frame numbers. Define whether cues live in local context time or resolved scene time, how nested context rescaling moves them, and how duplicates behave. Do not introduce a second generic `duration` spelling: retain the established `runtime` contract.

**Acceptance:** Nested Seq/Sync/Lag examples can explain exactly why an event starts at a particular time; cue lookup remains deterministic after context rescaling and repeated rendering.

**Anchors:** `algan/animation_timeline/animation_contexts.py`, `algan/animation_timeline/timeline.py`, `algan/scene.py`, `algan/viewer/`.

### R03 — P1: Unify background input semantics with a migration path

The constructor's ordinary Python callable currently receives one coordinate grid; render/setter paths support `(x, y, time)`, while kernel callables have their own scalar execution contract. `background=None` also initializes from `SETTINGS.style.frame` while rendering can resolve `SETTINGS.style.background`. These distinctions should not remain implicit.

Choose one documented author-facing Python protocol, preferably `(x, y, time)` with explicit broadcast shapes and coordinate ranges. Provide an explicit adapter for legacy grid callables. Do not catch arbitrary `TypeError` and guess another call signature: that would hide errors inside the user's function. Separate solid color, image, and procedural backgrounds in documentation and diagnostics, while retaining convenient direct values.

Document a single precedence table covering global default, constructor choice, persistent setter, one-render override, and reset. Test that table through real `save_frame`/`save_video` entry points, not only helper calls. The fixes in B01/B02 are deliberately smaller than this protocol migration.

**Anchors:** `algan/scene.py: __init__, set_background, save_frame, save_video`; `algan/settings/style_settings.py` and background rendering helpers.

### R04 — P1: Make process-level side effects explicit

The warm daemon provides substantial value, but eligible scripts can hand off during `import algan`. The README already warns that code before the import executes twice, normal exit behavior differs, and stdin is unavailable in the daemon. These are unusually consequential surprises for a library import.

Prefer explicit daemon selection at the CLI/editor boundary, or at minimum print an unambiguous execution-mode indicator and link failures to a fresh-process reproduction command. Preserve the existing `--no-daemon` / `ALGAN_USE_DAEMON=0` escape hatches and debugger handling. This is a product decision, not a reason to remove the daemon or its performance benefits.

Separately, package import sets Torch's default dtype and may set its default device. The previous global-autograd problem is already fixed; do not report it as still present. Remaining default-dtype/device effects deserve an integration test and a planned migration toward explicit tensor construction within Algan. Removing those calls alone could break code that relies on them, so this audit does not make that structural change.

**Anchors:** `README.md: The warm render daemon`; `algan/__init__.py`; `algan/daemon_client.py`; `algan/settings/_startup.py`.

### R05 — P1: Turn ownership, anchors and units into one concise contract

There are several individually valid concepts that are easy to confuse: constructing versus spawning; Group membership versus structural components; borrowed slices versus independent copies; an object's location/anchor versus its bounding-box center; relative movement versus absolute positioning; and degrees versus Manim's radians.

Create one task-oriented contract page with paired examples and link it from the relevant signatures and errors. Existing `move_center_to` already solves visual-center placement; surface it instead of inventing a duplicate. Explain that many pre-spawn edits are immediate setup, whereas spawned object changes record animations, and explain the scope of `Off` separately from structural hierarchy edits.

Use object names in ownership/layout errors. Show the distinction between editing an observational Group view and cloning objects before editing them. Preserve shared-parent behavior unless a separately reviewed ownership redesign is approved.

**Anchors:** `algan/animatable_base/mob_layout.py`, `mob_movement.py`, `mob_hierarchy.py`; `algan/mobs/group.py`; `agent_guidance/mobs_geometry.md`.

### R06 — P1: Improve discovery and typing without promising more than is checked

The curated root namespace and generated Manim adapter signatures are existing strengths. Do not replace them with uncontrolled star exports or add a second root spelling for every operation.

Add public authoring snippets that are checked for signature/help accuracy and gradually type-check representative scripts. Prioritize Scene's dual class/instance methods, fluent Mob return types, presets/settings overrides, context arguments, and tensor-valued easing functions. Some easing annotations currently describe a zero-argument callable even though easing transforms a value; fix annotations with contract tests rather than broad mechanical substitution.

Algan deliberately does not ship `py.typed`. Adding that marker makes downstream tooling rely on all annotations, so ship it only after a defined public typing subset passes. Generated stubs may be a useful intermediate step for the dynamic surface. Make `help(...)`, the Sphinx reference, and IDE signatures agree on units and accepted keywords.

**Anchors:** `algan/__init__.py`, `algan/mobs/manim_adapters.py`, `algan/animation_timeline/animation_contexts.py`, `.github/workflows/code_quality.yaml`, `DOCSTRINGS.md`.

### R07 — P1: Complete keyboard and stale-state UX in the viewer

The new asynchronous tests address incorrect overwrites, not the whole interaction design. Hierarchy names and expanders are clickable spans; the scrubber is a custom slider without dynamic value attributes; status messages are not declared as a live status region. Add keyboard-operable controls, a deliberate tree focus model, slider value reporting and Home/End behavior, and appropriate live announcements without announcing every video frame.

Also distinguish selected frame from last successfully displayed frame and show when inspector information belongs to an earlier playhead position. Define an update policy for attributes while scrubbing or playing, rather than firing unbounded expensive requests or leaving old values looking current. B11 separately fixes failed hierarchy expansion so it remains retryable.

Validate these changes in a real browser with keyboard-only and assistive-technology checks. Node state-machine tests are a useful gate but cannot establish accessibility or correct layout by themselves.

**Anchors:** `algan/viewer/static/index.html`, `viewer.js: nodeRow, seek, tick, updateReadouts, refreshState`, and `viewer.css`.

### R08 — P2: Make multi-output jobs previewable and transactional

Scene and Project now agree on the fixed directory-target case. The next step is one reusable output-plan object for video, stills, scene selection and frame selection. Preview every final filename, detect collisions up front, and state overwrite behavior before the first file is written.

Specify empty selections, repeated timestamps, scalar versus sequence `at`, relative paths, suffix inference, and how project IDs map to output names. Do not silently renumber established project outputs. A batch should validate all requested items before producing a partially successful directory, or return an explicit per-item result explaining partial completion.

This is a recommendation for stronger job semantics, not a claim that all these edge cases have been reproduced as failures in this audit. Preserve `RenderResult` and the existing list return for sequence still requests; avoid an incompatible return-type overhaul.

**Anchors:** `algan/project.py`, `algan/scene.py: save_frame, save_video`, `agent_guidance/api_settings.md`.

### R09 — P2: Clarify geometry and plotting choices before adding implementations

Names involving “circuit” can suggest that open curves are unsupported. That would be an inaccurate renderer assessment: `algan/mobs/nonplanar_circuit.py` already supports non-planar unfilled paths through split stroke runs, and the compatibility surface exposes curve-building tools. Improve discovery with an open-3D-path example and a clearly named native factory only if existing entry points remain awkward. Build on the current machinery rather than creating another renderer.

Likewise, legacy `AxesMob` / `FunctionPlotMob` and adapted plotting classes need a documented preferred workflow and a capability comparison. Do not blindly rename `AxesMob` to `Axes`: the adapter namespace can already occupy short names. Test discontinuities, label units, domain changes and animation before declaring one path canonical. Consolidation is more valuable than a third plotting family.

**Anchors:** `algan/mobs/nonplanar_circuit.py`, `bezier_circuit.py`, `plots.py`, `manim_adapters.py`, and `algan/manim/`.

### R10 — P2: Make color and material intent harder to misread

`Color` has RGB, glow and opacity channels. Ordinary tensor multiplication affects all channels: `BLUE * 0.5` both dims the color and halves opacity. CSS `"red"` is not the same numerical color as the curated `RED` palette constant. Neither is a bug, but both can look like rendering failures to a user.

Present channel-specific edits first in tutorials, label previews with their interpretation, and explain whether helper methods mutate or return a copy. Avoid mutating shared palette constants in examples. Treat eventual `with_*` naming as a coherent immutable-copy family, not isolated aliases.

Keep Three.js-style materials as the public model. Document the pre-spawn requirement for material/shader and geometry declarations alongside constructor examples. Distinguish appearance opacity, transmission, coverage/compositing alpha and glow; avoid describing all of them simply as “transparency.”

**Anchors:** `algan/constants/color.py`; material classes under `algan/rendering/`; `agent_guidance/api_settings.md`; `docs/source/advanced_user_tutorials/transparent_backgrounds.rst`.

## 3. Naming decisions

| Current surface | Recommendation | Priority and compatibility |
| --- | --- | --- |
| `AnimationContext.rewind(num_frames)` | Rename the keyword to `time` or `amount`, documenting context-local time and later retiming. It does not subtract a frame count. | P1. Accept the old keyword with a deprecation warning for a published migration window; do not silently reinterpret it as frames. |
| `.location` versus `get_center()` | Keep both meanings; consistently call location the anchor and the latter the visual/bounds center. Surface existing `move_center_to`. | P1 documentation. A bulk `.location` rename would be disruptive and unnecessary. |
| `tight_axis=0/1` | Offer descriptive enum/string values once the exact row/column behavior is specified; retain numeric values during migration. | P2. Avoid making callers memorize axis numbers. |
| `AxesMob`, `FunctionPlotMob` | Choose a preferred plotting namespace/workflow after comparing the native and adapted APIs. | P2. Do not create collisions with existing `Axes` or other adapted root names. |
| `BezierCircuitCubic` for open-path use cases | Document open paths prominently; consider an intent-revealing path factory backed by existing geometry. | P2 discovery/additive design, not a new renderer or wholesale class rename. |
| Color's `set_*` helpers that return copies | Consider a complete `with_*` copy vocabulary, or make current copy semantics unmistakable in signatures/examples. | P2. Confirm every helper's semantics before migration; no mixed mutating/copying convention. |
| Project `render_screenshots` versus Scene `save_frame` | Explain the distinction first; consider a unified output planner rather than adding several synonyms. | P3. Current names are understandable, and rename churn offers little immediate value. |
| `Seq`, `Sync`, `Lag`, `Off`, `runtime`, `SETTINGS`, `Scene.save_*` | Retain. Improve help and examples, not spellings. | These already form a compact, consistent authoring vocabulary. |

Every accepted rename should have one preferred spelling, an explicit compatibility period, a warning with a working replacement, updated examples, and a public-namespace/signature regression test. Do not automatically resurrect previously removed `run_time`, `duration`, `render_settings`, or module-level `render`/`view` APIs.

## 4. Important gotchas to teach rather than silently change

**Lifecycle:** An actor can belong to a scene without being spawned. Rendering is a request made after recording, not the immediate effect of constructing an object. Repeated rendering preserves authored state by default; `reset=True` is an explicit different operation. Existing state-preserving still export should not be described as missing.

**Timing:** Runtime can be applied by an enclosing context after its body finishes. A child's apparent local time and final scene time are not interchangeable. `Off` means instant authoring behavior, not “disable all scene state.”

**Geometry:** Layout generally depends on visible bounds, while transforms use anchors. Materials/shaders and relevant geometry declarations must be set before spawning. Root Algan adapters use Algan's angle conventions, while explicitly using the Manim compatibility namespace retains its own contracts.

**Quality:** Resolution, supersampling, ray samples, bounce count and post-processing are separate controls. “UHD” is not a complete explanation of render cost or convergence. Show the effective combination in the proposed render plan instead of introducing another opaque quality preset family.

**Settings:** `SETTINGS` sections have stable identity and presets are immutable. Use `SETTINGS.video.set(...)`, not section replacement. Settings consulted at render time require the override scope to cover rendering, not merely object construction.

**Dependencies:** `algan check` already exists. The next improvement is tying its diagnostics to the requested feature: Pango versus TeX text, model-import native libraries, audio alignment dependencies, encoder/alpha support, and the selected execution device. Do not treat every optional dependency as mandatory for every beginner.

## 5. Suggested implementation sequence and acceptance criteria

First merge the narrow correctness fixes after reviewing the recorded validation. Next, implement the render plan and shared background precedence/protocol tests. These make existing behavior explainable and give subsequent API work a common foundation.

Then add timeline inspection, ownership/coordinate guidance, and a small checked typing surface. Follow with viewer accessibility and explicit stale-state presentation, exercising real browser interactions in addition to the new asynchronous tests. Finally consolidate plotting/path discovery and strengthen multi-output planning based on actual author workflows.

For future UX fixes, prefer small scripts that demonstrate the user-visible failure, assertions that failures leave scene/timeline state unchanged, and compatibility tests around existing successful examples. A renamed method or new convenience feature should earn its place by removing an actual decision or ambiguity for authors.

## 6. Validation and limitations

Local source-isolated Python checks: **15 passed** after reproducing failures on the unmodified source. These exercise real source and Torch but replace unavailable renderer/registration boundaries; they do not establish full-package correctness.

Viewer client: **10 deterministic Node.js tests passed**. The original nine all failed against the original client; the hierarchy retry test was then added, reproduced its defect, and passed after B11. They cover out-of-order image, inspection and attribute requests, stale errors, cache ownership, resolution epochs and hierarchy retry behavior. A pytest wrapper runs these tests when Node is available and explicitly skips when it is absent.

Python syntax compilation, JavaScript syntax checking and `git diff --check` passed locally. The standard local `pytest -q --fast` attempt stopped during conftest import because `mapbox_earcut` was unavailable; other full-environment dependencies were also missing. No passing integration result is inferred from that attempt.

The first GitHub branch validation ran the checksum-verified patch, JavaScript tests and Python syntax checks, and formatted/linted changed Python files with the repository-pinned Ruff 0.12.4. With the locked full development environment on Ubuntu 24.04 / Python 3.11.16 / CPU, it confirmed:

- **50 targeted tests passed** in 0.67 seconds.
- **604 fast-suite tests passed**, 3,466 deselected, in 84.90 seconds, with two Quadrants template-mapper caching warnings.
- The initial fast run exceeded the repository's 75-second budget. Its time includes first-use work; no speedup or warm-time result is inferred from it, and no tests were removed to hide the warning.

Validation run: `34427555338`. A second branch validation (`34427955688`) includes B11, the complete portable `tests/unit_tests tests/fast` gate, and a subsequent warm fast run. The complete confirmed results, including the portable and warm runs, are recorded in [the validation record](UX_AUDIT_VALIDATION_2026-09-10.md).

The heavy full-render/path-traced baseline suites, GPU backends, real-browser interactions, assistive technology and rendered visual review are not covered by this audit. The portable fast render is a separate, pixel-compared check; its result is recorded in the validation record. No baselines were updated and no renderer performance or physical-correctness improvement is claimed.
